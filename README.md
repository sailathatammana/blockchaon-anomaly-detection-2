# Blockchain-Enabled Anomaly Detection in Educational Data with Autoencoders

A comprehensive machine learning system that combines **autoencoders for unsupervised anomaly detection** with **blockchain technology for data integrity** in educational settings. This project detects unusual patterns in student engagement and performance while maintaining tamper-resistant logs of all observations.

**NEW:** This version uses **REAL student outcome data** (Pass/Fail/Withdrawn) instead of synthetic anomalies, providing realistic and trustworthy anomaly detection results.

## Project Overview

### Background and Motivation

Educational platforms generate vast amounts of data from student interactions. Anomaly detection in this data can identify:
- Students at risk of failing or dropping out
- Unusual engagement patterns
- Sudden disengagement
- Potential learning difficulties

By combining autoencoders (powerful unsupervised ML for anomaly detection) with blockchain (distributed ledgers for data integrity), this system ensures both **detection accuracy** and **data trustworthiness**.

### Key Innovation: Real Data Labeling

Instead of injecting synthetic anomalies, this system uses **actual student outcomes** as ground truth:
- **Normal:** Students who passed or excelled (Pass, Distinction)
- **Abnormal:** Students who failed or withdrew (Fail, Withdrawn)

This approach ensures:
- ✅ Realistic anomaly detection (not perfect 99% accuracy)
- ✅ Better generalization to production deployment
- ✅ Transparent, auditable labeling strategy
- ✅ Educationally meaningful results

## Evaluation Metrics

### Standard Metrics (Both Models)
- **Accuracy** — Fraction of correct predictions
- **Precision** — Of students flagged as at-risk, how many actually are?
- **Recall** — Of actual at-risk students, how many did we catch?
- **F1 Score** — Balanced measure (harmonic mean of precision and recall)
- **ROC AUC** — Threshold-independent performance measure

### Interpretation
With real data, expect:
- **Accuracy:** 80-90% (honest performance, not perfect)
- **Precision:** 80-90% (some false alarms acceptable)
- **Recall:** 75-85% (catch most at-risk students)
- **F1 Score:** 0.80-0.87 (realistic balance)
- **ROC AUC:** 0.80-0.90 (clearly beats random guessing)

## Isolation Forest Baseline

**Location:** `scripts/isolation_forest_baseline.py`

Isolation Forest is a tree-based ensemble method that:
- Isolates observations through random feature/split selection
- Relies on principle that anomalies are "few and far between"
- Provides O(n log n) time complexity, efficient for large datasets
- Makes no assumptions about data distribution

### Three Training Strategies

| Strategy | Training Data | Use When | Pros | Cons |
|----------|---|---|---|---|
| **normal_only** | Normal students only | Want conservative approach | Fewer false positives | May miss some anomalies |
| **all_data** | All students | Know true contamination | Uses outcome knowledge | Sensitive to proportion |
| **informed** | All students + buffer | Production deployment | **RECOMMENDED** — robust | N/A |

## Autoencoder Method

The autoencoder architecture:
```
Input (55 features)
   ↓
Dense 128 neurons + ReLU
   ↓
Dense 64 neurons + ReLU
   ↓
Dense 32 neurons + ReLU
   ↓
BOTTLENECK: 4 neurons (extreme compression)
   ↓
Dense 32 neurons + ReLU
   ↓
Dense 64 neurons + ReLU
   ↓
Dense 128 neurons + ReLU
   ↓
Output (55 features - reconstruction)
```

**How it works:**
1. Compress normal behavior through bottleneck
2. Reconstruct input from compressed version
3. Measure reconstruction error: `error = ||input - output||²`
4. High error = Anomalous behavior detected

**Why unsupervised on normal-only?**
- Normal data reconstructs well (low error ~0.05-0.15)
- Abnormal data cannot fit through bottleneck (high error ~0.2-0.5)
- Clear separation enables reliable anomaly detection

### Label Source

Anomaly labels are created from the `final_result` field in studentInfo.csv:
```
Pass          → Label: +1 (Normal - successful completion)
Distinction   → Label: +1 (Normal - excellent performance)
Fail          → Label: -1 (Abnormal - failed course)
Withdrawn     → Label: -1 (Abnormal - dropped out)
```

This provides a realistic, auditable labeling strategy grounded in actual student outcomes.
